## Remaining verified limitations and risks

1. **The backlink endpoint still has a meaningful synchronous stress cost.** Its recorded single-run synthetic probe with page limit 1, 1,000 links and 1,000 shared ancestors takes **1,255ms**, also delaying the timer 1,255ms and issuing 1,001 recursive queries. This is improved from 5,062ms; it is not page-size-bounded execution. The full endpoint aggregate revision still visits all active links ([apps/api/src/quick-notes/record-link-revision.ts](</Users/serhiinadtochii/Projects/personal-server/apps/api/src/quick-notes/record-link-revision.ts:14>)). Evidence: [output/ps110/backlink-after.json](</Users/serhiinadtochii/Projects/personal-server/output/ps110/backlink-after.json:11>). Treat this as a measured scalability limitation with an explicit supported workload/performance budget, not an unproven production outage or a reason to truncate privacy/revision checks. A future optimization could maintain an invalidation/version aggregate transactionally, provided it preserves authorization-relevant dependency changes; it needs a separate design and benchmark.

2. **Fresh review independence degraded under capacity pressure.** PS-108 onward reused idle role contexts, with the limitation honestly recorded. Reusing someone as a different named role does not give fresh independent context. The reviews still found useful defects, but four role labels should not be counted as four clean independent perspectives. [claudedocs/tickets/in-progress/PS-103/tasks/PS-108/04-review.md](</Users/serhiinadtochii/Projects/personal-server/claudedocs/tickets/in-progress/PS-103/tasks/PS-108/04-review.md:3>); [claudedocs/tickets/in-progress/PS-103/tasks/PS-109/04-review.md](</Users/serhiinadtochii/Projects/personal-server/claudedocs/tickets/in-progress/PS-103/tasks/PS-109/04-review.md:7>); [claudedocs/tickets/in-progress/PS-103/tasks/PS-110/04-review.md](</Users/serhiinadtochii/Projects/personal-server/claudedocs/tickets/in-progress/PS-103/tasks/PS-110/04-review.md:3>).

3. **High test counts hid integration and scale gaps until a different boundary was exercised.** PS-110's isolated Task dialog test bypassed production wiring; the replacement integrated editor/panel test caught the real failure. PS-109's component pass did not catch actual keyboard focus until browser use. Existing privacy lineage tests did not model many retained/deleted relationships. These are reasons to specify behavioral boundary, adversarial state and workload during planning, not merely demand more tests or reviewers. Useful current tests include [apps/web/src/features/quick-notes/record-link-panel.spec.tsx](</Users/serhiinadtochii/Projects/personal-server/apps/web/src/features/quick-notes/record-link-panel.spec.tsx:249>), [apps/api/src/assistant/record-link-history-scale.spec.ts](</Users/serhiinadtochii/Projects/personal-server/apps/api/src/assistant/record-link-history-scale.spec.ts:148>), and [apps/api/src/privacy/sqlite-policy-snapshot.spec.ts](</Users/serhiinadtochii/Projects/personal-server/apps/api/src/privacy/sqlite-policy-snapshot.spec.ts:92>).

4. **Hermes compatibility is deliberately deep and expensive to preserve.** The adapter replaces private methods/constructors and disables multiple execution paths ([deploy/hermes/runtime_adapter.py](</Users/serhiinadtochii/Projects/personal-server/deploy/hermes/runtime_adapter.py:177>)). Hash pinning and real native fixtures help, and container isolation is explicitly the stronger boundary, but upgrades need their own compatibility/negative-test gate. This is an architectural maintenance risk, not a new demonstrated exploit. Do not credit tests of this pinned runtime as proof about another revision.

5. **Request recovery has many representable combinations.** The frontend stores phase, pending, preview, result, recovery target and unconfirmed execution independently ([apps/web/src/features/assistant/command-state.ts](</Users/serhiinadtochii/Projects/personal-server/apps/web/src/features/assistant/command-state.ts:21>)); the corrected bugs concerned interactions between them. It currently has meaningful sequence regressions. A future discriminated transition model could make impossible combinations harder to represent, but a large speculative rewrite during the epic would add risk. Preserve the observed sequence tests as the contract first.

6. **PS-110 is not closed and its fixtures have not been audited for present liveness.** The final artifact still owns API/proxy resources and queues browser verification. This audit did not contact or stop those processes. Treat PID/session fields as last recorded ownership, not confirmation those processes still exist. ## Implications for a Codex ticket runner

- Preserve bounded ticket steps and domain-level acceptance. PS-105/107/108/110 show that “one ticket” can still contain multiple transactions/protocols and expensive verification; tickets are orchestration units, not guaranteed equal-size units.
- Put the test plan in the ticket before source edits: exact boundaries, supported failure cases, expected resource cost and whether browser interaction adds product evidence. PS-108's human/Inbox browser regression is valid but does not prove its new Task API; do not present a generic browser checkpoint as new-feature acceptance.
- Separate authoritative current status from append-only history. Store last verified source digest, phase, unresolved findings, pending check, evidence pointers and owned resources in one concise checkpoint. Historic prose may remain a log, but must not compete with the current headline.
- A review manifest must enumerate **tracked diff plus untracked source** and bind to the actual snapshot. The run already created per-ticket `/tmp/ps110-before` and a 64/67-file packet because the epic was intentionally uncommitted. Persist equivalent machine-readable snapshot evidence in a durable owned directory; `/tmp` alone is not a resumption contract.
- Scale review to the changed boundaries. Security-critical disclosure/retention/isolation deserves specialized scrutiny; a focused route/dialog fix needs relevant independent review and its behavioral regression, not a mandatory full cast respawn and full suite repeated without new risk.
- Complete evidence-driven fixes automatically within authorization. Capacity, suite contention and missing fixture assets are operational recovery problems; they should not become product-choice questions. Genuine missing account/cutover authorization remains a distinct future readiness gate.

No new high-confidence user-visible correctness/security defect is asserted by this bounded audit beyond the explicitly measured remaining performance limitation and recorded closure/evidence gaps. That is a limit on this audit, not certification that the entire 393-file working tree is defect-free.
