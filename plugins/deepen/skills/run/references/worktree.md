# The run worktree

Authoritative text for the worktree a `deepen:run` works in: its names, how stage 2 creates it,
how stage 4 and every later stage bind or re-attach it, the `.worktreeinclude` copy and its
exclusion list, the dependency install, the worktree's part of an abort, and teardown.

- **Stage 2 creates it**, before the inventory commit, so the inventory commit lands on the run
  branch directly on top of `<BASE_SHA>`.
- **Stage 4** ([stage-4-implement.md](stage-4-implement.md)) **and every later stage bind it**
  per §3, re-attaching it only when it is absent. No stage after 2 ever cuts a fresh one.
- **A run never works in the clone root.** The isolation is the point: the clone stays on `base`,
  clean, for the next run's preflight ([preflight.md](preflight.md) §3).

`<CLONE>`, `<BASE_SHA>` and `<state_dir>` are bound by [preflight.md](preflight.md); `<run-id>`
and `<slug>` are generated by the run skill.

---

## §1 Names

- `<WT>` = `<CLONE>/../<clone-dirname>-worktrees/<run-id>` — a sibling of the clone, never inside
  it ([profile.md](../../setup/references/profile.md) §2 `loop_clone`).
- `<branch>` = `deepen/<run-id>-<slug>`.

Both reach command lines, so both are checked **before first use**:

- `<run-id>` matches `^[A-Za-z0-9._-]+$`, `<slug>` matches `^[a-z0-9-]+$` — checked without a
  shell.
- `git check-ref-format --branch "<branch>"` succeeds.

A failure aborts the run naming the value. Every path in this file is quoted wherever it reaches
a shell — `<CLONE>`'s own directory name may contain spaces.

---

## §2 Create (stage 2, before the inventory commit)

```bash
git -C "<CLONE>" worktree add "<WT>" -b "<branch>" "<BASE_SHA>"
```

Then §4 and §5, in that order.

Failure aborts the run. **Never fall back to working in the clone root.** A `worktree add` that
fails because `<branch>` already exists means a dead run left its branch behind: abort and name
it rather than attaching to work nobody can vouch for.

---

## §3 Bind or re-attach (stage 4 and every later stage)

1. Run `git -C "<CLONE>" worktree prune`, so a registered worktree whose directory was removed
   by hand no longer counts as present.
2. **Present** — `git -C "<CLONE>" worktree list --porcelain` lists `<WT>` on
   `refs/heads/<branch>` → bind it. Re-read the exclusion list from
   `<state_dir>/runs/<run-id>/exclusions` (§4).
3. **Absent, and the branch exists** — `git -C "<CLONE>" rev-parse --verify "refs/heads/<branch>"`
   resolves → re-attach it:

   ```bash
   git -C "<CLONE>" worktree add "<WT>" "<branch>"
   ```

   then run §4 and §5 again: a re-attached worktree has neither the copied files nor the
   installed dependencies.
4. **Absent, and no branch** → abort: `worktree: <branch> not found — the run branch and its
   inventory commit are gone`. There is nothing to attach to, and cutting a fresh branch would
   implement against no oracle.

A worktree registered at `<WT>` on any other branch aborts the same way, naming the branch it is
on.

---

## §4 Copy and the exclusion list

Copy every file matching a `.worktreeinclude` pattern from `<CLONE>` into `<WT>`, preserving
relative paths. No `.worktreeinclude` in the repo → skip the copy, no error.

**Then verify every copied path is still ignored in the worktree.** The worktree evaluates ignore
rules against the committed ignore files at `<BASE_SHA>`, while the patterns that selected the
files were matched in a working tree, so a file ignored where it was copied from can arrive
unignored:

```bash
git -C "<WT>" check-ignore -q -- "<each copied relative path>" || echo "not ignored: <path>"
```

Every path that comes back not ignored:

- is named in the stage report with its remedy (add it to the committed ignore file);
- joins the run's **exclusion list**, written one path per line to
  `<state_dir>/runs/<run-id>/exclusions` — so a resumed or later stage re-binds the same list;
- is unstaged with `git -C "<WT>" reset -q -- "<path>"` before **every** commit the run makes;
- is named in every agent brief as never-stage;
- is the **only** exemption from the clean-tree assertion ([fence.md](fence.md) §7).

This is the one check between a copied secrets file and a pushed branch.

The dev server's untracked residue joins the same list, with its own report line
([dev-server.md](dev-server.md) §5).

## §5 Install

`app.install` null → skip, with the report line `install: skipped — app.install is null`.

Otherwise the command runs under the profile's script-file rule
([profile.md](../../setup/references/profile.md) §3): write the `app.prelude` line (when set)
and then the `app.install` line, each **verbatim**, into
`<state_dir>/runs/<run-id>/install.sh` with `Write`, and execute that file:

```bash
cd "<WT>" && bash "<state_dir>/runs/<run-id>/install.sh"
```

The path is fixed and run-keyed because shell state does not survive between tool calls. A red
install aborts the run.

---

## §6 Path binding

Every command after §2 or §3 is explicitly path-bound — `git -C "<WT>" …` or
`cd "<WT>" && …`. Shell state does not persist between tool calls, so an unbound command silently
operates on the clone root instead.

---

## §7 Abort — the worktree's part

Every abort the run takes after §2 created the worktree performs, in order:

1. **Stash the branch diff** — `git -C "<WT>" diff "<BASE_SHA>..HEAD"` into
   `<state_dir>/reports/<run-id>/abort.patch`. The branch diff, not the working-tree diff: past
   an agent commit the tree is clean-asserted, so the working-tree diff would be empty.
2. **Write the deciding evidence** to `<state_dir>/reports/<run-id>/abort.md` — the line that
   aborted the run, the assertion or check that decided it, and the sets, paths or output tail it
   compared, so a human can read what happened without re-running anything.
3. **Remove the worktree** — `git -C "<CLONE>" worktree remove --force "<WT>"`, then
   `git -C "<CLONE>" worktree prune`. `--force` is correct here: the diff is already stashed.
4. **Clear the fence file** — remove `<common-dir>/deepen-fence.json` ([fence.md](fence.md) §1).
5. **The run skill releases the lock**, last, per [preflight.md](preflight.md) §2.

The run branch is kept: its commits are what a human inspects. An abort before §2 created the
worktree skips steps 1 and 3.

Both evidence files sit inside `reports/<run-id>/`, in the state layout
([profile.md](../../setup/references/profile.md) §5); an abort creates no other directory.

---

## §8 Teardown (a delivered run)

Remove the worktree only when both hold — the status read NUL-delimited per [fence.md](fence.md) §7:

```bash
git -C "<WT>" status --porcelain -z --no-renames          # empty, exclusion-list paths aside
git -C "<CLONE>" rev-parse --verify "refs/heads/<branch>" # resolves
```

```bash
git -C "<CLONE>" worktree remove "<WT>"
git -C "<CLONE>" worktree prune
```

The predicate keeps uncommitted work from being discarded: once the commits are on `<branch>`,
the worktree holds nothing the repository does not. `--force` is permitted only to clear what
`app.install` created or the exclusion-list copies, never to discard commits. Predicate fails →
leave the worktree in place and print its path.

Clear `<common-dir>/deepen-fence.json` in either case.
